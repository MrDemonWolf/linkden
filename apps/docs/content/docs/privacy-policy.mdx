**Last updated:** November 2026

This page describes the LinkDen documentation site at `mrdemonwolf.github.io/linkden` and the data handling in the current project source. A self-hosted instance is operated by its owner; that instance's own policy and configured providers apply.

## Documentation site

The docs are a static GitHub Pages site. The current source does not add application visitor analytics or advertising trackers. Search uses the site's static index. Display preferences, such as theme, may be stored in the browser.

GitHub processes hosting/request information under its [Privacy Statement](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement). Loading a hosted site is not a promise that its hosting provider receives no IP address or request metadata.

## Data held by a self-hosted instance

The operator controls its database, storage, backups, publication settings and integrations. Depending on the configured features, records can include:

- Profile information, blocks, social links, images, public branding and vCard contact details.
- Admin account/authentication data, two-factor configuration, recovery material and session security metadata.
- Contact submissions: the submitted name, email, message and any enabled optional meeting question.
- Settings and private integration/signing credentials.
- Audit records, publication jobs and frozen/approved source required for publication and recovery.
- Previously collected historical profile view/click records, if that instance still retains them.

Cloudflare D1/R2 and the configured deployment/state/backup services process or store the relevant data. This is self-hosting in the operator's account, not a claim that no service provider can process the data. See [Cloudflare's Privacy Policy](https://www.cloudflare.com/privacypolicy/) for the provider's policy.

## Collection is Off

Profile page-view and button-click collection is retired in this source. The current public renderer sends no profile analytics events. Legacy records are left in existing databases until the operator explicitly chooses to delete them.

Historical records can remain in the database and backups under the previous methodology. Their presence does not mean current collection is active. The retired profile dashboard is removed; protected historical read APIs and backup compatibility remain.

Hosting providers may still process ordinary request/security information. Contact submissions, authentication, CAPTCHA and embedded media have separate purposes and behavior.

## Public publication

Opt-in native publication creates public files from approved profile content. The builder excludes private settings and unpublished future content from public artifacts; the separate approved scheduling source stays private.

An enabled GitHub publication workflow processes the approved build and retains public artifacts according to its configured retention. Previously published files or provider versions can remain accessible until the operator replaces or withdraws them. Deleting editor data or resetting D1 does not automatically remove the separate published site. Database backups and exported files also have their own retention.

## Contact forms, email and external content

- **Contact forms:** configured delivery can store submissions in the Inbox and/or send them by email. Failed or unavailable notification delivery falls back to the Inbox. Server-side validation, throttling, CAPTCHA and a daily reservation limit protect the action; rejected requests can still be processed by the hosting/security layer.
- **Resend:** configured password-reset, email-change, magic-link and contact-notification delivery sends the necessary message/address data to the email provider. Unconfigured or unsupported providers do not send. See [Resend's Privacy Policy](https://resend.com/legal/privacy-policy).
- **CAPTCHA:** a configured Turnstile, reCAPTCHA or hCaptcha widget contacts its provider. Server verification includes the submitted token and transient visitor IP address. CAPTCHA is separate from analytics consent.
- **Embeds:** YouTube, Spotify, SoundCloud or a configured custom embed receives browser requests when loaded, including the visitor's IP address. With the consent banner enabled, embeds wait for an explicit load action or permission for Embedded media. Disabling that banner permits direct loading.
- **External images and links:** retained third-party image URLs are requested by the browser; following a link contacts its destination. A static snapshot does not make those providers local.
- **Gravatar:** the admin UI can request an avatar using an MD5 hash of the admin email when no uploaded image is set. Public visitors do not use that admin avatar lookup.
- **Maps:** Location blocks provide outbound map links; the map provider is contacted when the visitor follows the link.
- **GitHub:** Settings → Data performs a server-side version lookup. Enabled publication automation also uses GitHub; it is not the application's only possible outbound integration.

Embedded-media consent choices and theme preferences can use browser storage. They do not activate retired profile collection.

## Retention and deletion

The current daily maintenance defaults prune contact submissions and legacy analytics older than 365 days, audit entries older than 180 days, and expired sessions/verification records. Actual removal depends on successful scheduled execution. Exports, provider logs, emails, R2 backups and published versions have separate retention; deleting a database row does not recall those copies.

Operators can use the protected data tools to export or delete stored content. Before making a privacy request, identify the operator of the particular instance: the open-source project's maintainers cannot access every self-hoster's database. Removing public content also requires the operator's publication/takedown procedure.

## Contact

For this documentation site's policy, [open a project issue](https://github.com/MrDemonWolf/linkden/issues). For information stored by another LinkDen instance, contact the operator identified on that instance.
