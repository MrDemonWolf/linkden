---
title: Installation
description: Install dependencies and run the editor and API locally.
---

Use Bun for repository commands and Node.js 24 for Alchemy. The repository pins Bun in `package.json`; use that version when reproducing CI.

## Clone and install

```bash
git clone https://github.com/MrDemonWolf/linkden.git
cd linkden
bun install --frozen-lockfile
```

## Choose a local development path

### Alchemy development

`bun run dev` starts the API, web app, and docs through the workspace tasks. Alchemy applies local migrations and uses the shared state-store Worker, so this path needs its configured `ALCHEMY_STATE_TOKEN`. Follow the [state-store setup](/docs/self-hosting/cloudflare#alchemy-state) first.

Copy `.env.example` into Alchemy's `packages/infra/.env` and replace the example secret:

```bash
cp .env.example packages/infra/.env
openssl rand -base64 32
bun run dev
```

The five app URL/auth values in the example are required. Alchemy also loads app-level `apps/web/.env` and `apps/server/.env` in development. See [Configuration](/docs/getting-started/configuration) for file locations and production differences.

### Standalone API and web

This path uses Wrangler's local D1 and R2 emulation without the Alchemy state store.

Create `apps/server/.dev.vars` with a generated secret:

```dotenv
BETTER_AUTH_SECRET=replace-with-your-generated-secret
BETTER_AUTH_URL=http://localhost:3001
CORS_ORIGIN=http://localhost:3001
```

Create `apps/web/.env.local`:

```dotenv
NEXT_PUBLIC_SERVER_URL=http://localhost:3001
NEXT_PUBLIC_SITE_URL=http://localhost:3001
INTERNAL_SERVER_URL=http://127.0.0.1:3000
```

The browser uses one origin, `http://localhost:3001`, for the page, authentication, and API calls. The web app bridges API requests to the private local listener on port 3000.

From the repository root, apply local migrations before first use and after pulling new migrations:

```bash
bun run --cwd apps/server wrangler d1 migrations apply linkden-db --local
```

Run these in separate terminals:

```bash
bun run dev:server
```

```bash
bun run dev:web
```

Start the documentation site separately when needed:

```bash
bun run --cwd apps/docs dev
```

| App | Local URL |
| --- | --- |
| Editor and public development page | `http://localhost:3001` |
| API listener / health check | `http://localhost:3000` |
| Documentation | `http://localhost:3002` |

The Alchemy and standalone paths use separate local databases. Switching paths does not move your account or content. Keep listeners local; development login is unavailable through tunnels or nonlocal hostnames.

## Complete setup

Open `http://localhost:3001`. Until an admin exists, it redirects to `/admin/setup`. The wizard takes you through **Account → Profile → Theme → Done**. The first account becomes the single administrator; subsequent registration is blocked.

Open the editor, save a profile change, and reload to confirm persistence. Enable [two-factor authentication](/docs/guide/security#two-factor-sign-in) before using a public instance.

## Development checks

```bash
bun run check-types
bun run lint
bun run format:check
bun run test
bun run build
```

Use `bun run test` for Vitest; `bun test` invokes a different runner. Database schema changes go through checked-in migrations. `bun run db:generate` is for contributors changing schemas, not routine installation. Avoid resetting an existing database to solve setup problems.
