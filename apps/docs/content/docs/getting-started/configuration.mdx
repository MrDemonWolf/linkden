Keep deployment secrets in the environment and ordinary preferences in the admin. Public page changes on an assets-only deployment need a successful publication after saving.

## App environment

Start from `.env.example`. Generate a real secret with:

```bash
openssl rand -base64 32
```

| Variable | Purpose |
| --- | --- |
| `BETTER_AUTH_SECRET` | Private authentication secret; use at least 32 random characters |
| `BETTER_AUTH_URL` | Browser-facing auth origin; locally `http://localhost:3001` through the web bridge |
| `CORS_ORIGIN` | Exact trusted editor origin, including protocol and no trailing slash |
| `NEXT_PUBLIC_SERVER_URL` | Browser-facing API origin; locally `http://localhost:3001`, embedded in the frontend build |
| `NEXT_PUBLIC_SITE_URL` | Public profile origin for metadata and links |

Empty secrets fail closed. Outside plain-HTTP loopback, short or placeholder secrets also disable authentication. Production deployment validates these values before changing resources.

### Where local values go

- **Alchemy development:** `packages/infra/.env` first, with `apps/web/.env` and `apps/server/.env` supplying unset development values.
- **Standalone API:** `apps/server/.dev.vars`.
- **Standalone web:** `apps/web/.env.local`.
- **Standalone web API bridge:** set `INTERNAL_SERVER_URL=http://127.0.0.1:3000`; only a bare plain-HTTP loopback origin is accepted.

```dotenv
# API values
BETTER_AUTH_SECRET=replace-with-your-generated-secret
BETTER_AUTH_URL=http://localhost:3001
CORS_ORIGIN=http://localhost:3001

# Web values
NEXT_PUBLIC_SERVER_URL=http://localhost:3001
NEXT_PUBLIC_SITE_URL=http://localhost:3001
INTERNAL_SERVER_URL=http://127.0.0.1:3000
```

Use port 3001 for all browser-facing local URLs. The API listener and its health route remain on port 3000; `INTERNAL_SERVER_URL` connects the web bridge and server-side requests to it.

Restart the frontend after changing public environment values. Do not put private keys in a `NEXT_PUBLIC_*` variable.

### Deployment origins

The legacy same-host deployment uses one public HTTPS origin for auth, CORS, the browser API, and the profile.

The opt-in split topology uses separate public and admin origins. The admin reaches its private API through a service binding; public profile assets are published separately. Do not switch an existing deployment by changing a few URLs: follow the [Cloudflare guide](/docs/self-hosting/cloudflare) and [environment reference](/docs/self-hosting/environment-variables). Access policies, alternate-host closure, public contact ingress, and staged verification remain deployment gates.

## Authentication

Setup at `/admin/setup` creates one administrator. Set `SETUP_TOKEN` before exposing a fresh instance, then enter it in the wizard to prevent someone else claiming the first account.

Under **Settings → Account**:

- Enable **Two-factor authentication**, scan the QR code or enter its key, verify a TOTP, and save the backup codes. Enrollment is incomplete until that first code verifies.
- After password sign-in, enter a TOTP or a single-use backup code. The optional trusted-device choice lasts 30 days.
- Enable **Magic link** only after configuring email and while two-factor is off. Links expire after ten minutes and never create another account.
- Change your password or start the email-change confirmation flow.

Email recovery requires configured Resend delivery. Without it, the login page explains operator recovery. See [Security](/docs/guide/security) for the password-reset command.

### Local development login

`DEV_LOGIN="true"` belongs only in the standalone API's gitignored `.dev.vars`. `NEXT_PUBLIC_DEV_LOGIN=true` can show the matching local frontend button.

Both the configured auth URL and the actual request must pass strict plain-HTTP loopback checks. Non-development runtime modes, tunnels, forwarded hosts, public pages, and nonlocal origins cannot use it. Alchemy never binds the bypass into deployed Workers. Use real credentials for remote previews.

## Find the right setting

| Area | What it controls |
| --- | --- |
| **Profile page → Profile / Social** | Profile details and social links |
| **Design → Theme / Banner / Branding / SEO** | Public layout, 11 presets, color overrides, images, legal text, vCard, consent, and share metadata |
| **Inbox** | Messages and the **Accepting messages** switch |
| **Settings → Account** | Security, account details, timezone, and editor preferences |
| **Settings → Email** | Resend API key, sender, and contact delivery |
| **Settings → Integrations** | CAPTCHA provider, site key, and secret |
| **Settings → Wallet** | Pass design, private download switch, identity, and signing material |
| **Settings → Data** | Backup/import, LinkStack migration, and confirmed destructive actions |

Dedicated login-background and login-logo controls have been removed; sign-in uses normal site branding. MapKit settings remain accepted for compatibility, but the Integrations page no longer offers a map embed. Location blocks open an outbound map link.

The admin footer contains LinkDen branding, build/development information, and the editor theme control. Public themes and public branding are separate settings.
