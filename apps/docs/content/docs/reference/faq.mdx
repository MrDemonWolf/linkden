## What is LinkDen?

A self-hosted, MIT-licensed profile page builder with one administrator per instance.

## Is hosting free?

The software is free to use under the MIT license. Cloudflare services, a domain, email delivery, Apple membership, and traffic can have their own charges and quotas. A free account does not guarantee that every build, authentication workload, or traffic level fits its limits.

## Can I use it commercially or remove branding?

Yes, subject to the MIT license. Public footer branding is under **Design → Branding**; admin branding is under **Settings → Account**. Keep required license notices when distributing the software.

## Where does it run?

The supported deployment uses Cloudflare Workers, D1, and R2, managed through Alchemy. The separately published public target uses native static assets. The docs site is a static export. See [Self-hosting](/docs/self-hosting/cloudflare).

## Does it support multiple administrators?

No. Setup creates one administrator, and a database trigger prevents a second account. Deploy separate instances for separate profiles.

## Why did saving not change my public page?

Saving updates authoring data. Include new blocks with **Apply n new**. **No block drafts** confirms only that all blocks are applied. The legacy dynamic page reads enabled, applied blocks immediately; an assets-only public page needs the header's separate **Publish** action, a configured target and runner, and a verified publication receipt.

**Published** means a verified publication receipt. An unavailable publisher or a failed build does not make a saved draft live.

## Is the preview interactive?

It is a visual preview in a plain page canvas. Scroll and switch light/dark mode there; use **View live** to test links, embeds, contact submissions, and downloads. The preview may show drafts and unsaved edits that are absent from the public page.

## Can desktop and mobile have different layouts?

Choose **Side by side** or **Stacked** under **Design → Theme**. Side by side keeps the profile sticky beside a vertical list on wide pages. Mobile always stacks the profile and all blocks in one column.

## How many themes and block types are available?

There are **11 public theme presets**, each with light and dark palettes, plus custom colors and CSS. The nine block types are Link, Header, Embed, Connect, vCard, Location, Image, Text, and Divider. Social icons are separate.

The admin uses its own neutral light/dark appearance. Changing its theme does not overwrite your public design.

## Does LinkDen collect profile analytics?

Profile pages and buttons send no LinkDen analytics beacons. Historical records remain available through protected APIs; no analytics dashboard or collection job is enabled.

## How do I reset my password?

Use **Forgot password?** on the login page when Resend is configured. A password reset signs out existing sessions.

Without email, an operator with the repository and database access can run this from the repository root:

```bash
bun run reset:password -- --email you@example.com --remote
```

The command prompts for the new password. Confirm the intended database using the [recovery instructions](/docs/guide/security#account-recovery) before using `--remote`.

## What if I lose my authenticator?

Use an unused backup code. If none remain, an operator can reset the password with `--disable-2fa`, then enroll again and save new backup codes. The recovery command changes account security; use it only for the instance you administer.

## Why is Dev sign-in unavailable?

It works only with an explicitly enabled standalone local API and strict plain-HTTP loopback configuration. It is unavailable on deployed sites, tunnels, nonlocal hosts, or explicit non-development runtimes. Use your real account remotely.

## How do I troubleshoot failed admin requests?

Check that both local servers are running and that your browser API URL, auth URL, and exact CORS origin match the [configuration](/docs/getting-started/configuration). Restart the frontend after public environment changes. A weak secret produces a named authentication configuration error instead of a working login.

The recommended local setup uses `http://localhost:3001` for `BETTER_AUTH_URL`, `NEXT_PUBLIC_SERVER_URL`, and the editor origin. Set `INTERNAL_SERVER_URL=http://127.0.0.1:3000` in the standalone web environment so the bridge reaches the actual API listener.

For a type/build problem, run `bun run check-types` and inspect its actual error; missing dependencies and environment values are different problems.

## How do I update an existing installation?

Preserve local changes and take a verified backup before updating. Review the release notes and migration requirements, install the locked dependencies, and run the repository checks. Deploy only through your approved Alchemy workflow.

Do not generate new migrations just to upgrade, reset a database to resolve a migration error, or assume a code rollback reverses schema or data changes. See the [Cloudflare guide](/docs/self-hosting/cloudflare) for the deployment procedure.
