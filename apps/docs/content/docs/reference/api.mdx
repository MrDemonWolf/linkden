LinkDen's API is built with [tRPC](https://trpc.io/) v11 on [Hono](https://hono.dev/), running on Cloudflare Workers. Every call is end-to-end type-safe -- no code generation required.

## Architecture

```
Next.js Frontend (apps/web)
       |
       | tRPC Client (HTTP requests)
       |
       v
Hono Server (apps/server)
       |
       |-- Better Auth (session validation)
       |-- tRPC Router (packages/api)
       |
       v
Drizzle ORM (packages/db)
       |
       | SQL queries
       |
       v
Cloudflare D1 (SQLite)
```

- **Hono** -- API request handling on Cloudflare Workers.
- **tRPC v11** -- End-to-end type safety. Router definitions live in `packages/api`.
- **Better Auth** -- Email/password authentication. Session cookies validated on protected procedures.
- **Drizzle ORM** -- Type-safe SQL for Cloudflare D1. Schema lives in `packages/db/src/schema/`.

The web app shares an API transport: a private Cloudflare service binding when available, or a validated loopback transport for local development. The opt-in split topology publishes profile HTML, media, vCards, and OG images separately as static artifacts. Visiting that static profile does not fetch this API or probe the admin session.

## Authentication

LinkDen uses [Better Auth](https://www.better-auth.com/) with email/password sign-in, optional TOTP two-factor and an optional magic link. Auth routes live under `/api/auth/*`.

### Session Flow

1. Create an admin account during first-time setup at `/admin/setup` (with the `x-setup-token` header when `SETUP_TOKEN` is set).
2. Sign in at `/admin/login`. With two-factor on, Better Auth answers the password step with `twoFactorRedirect` and the login page asks for a TOTP or backup code.
3. Better Auth issues a secure session cookie, sent with every API request to authenticate protected procedures.

### Environment Variables

| Variable | Description |
|----------|-------------|
| `BETTER_AUTH_SECRET` | Secret key for session signing (32+ characters outside localhost, or auth answers 503) |
| `BETTER_AUTH_URL` | Browser-facing auth origin; recommended local value `http://localhost:3001` |
| `CORS_ORIGIN` | Trusted origin for the frontend |
| `NEXT_PUBLIC_SERVER_URL` | Browser-facing API origin; recommended local value `http://localhost:3001` |
| `INTERNAL_SERVER_URL` | Standalone web bridge/server-side transport; locally `http://127.0.0.1:3000` |

The recommended local setup keeps page, auth, and browser API requests on port 3001. The web bridge forwards to the actual API listener on port 3000, where `/api/health` can be checked directly.

Generate a secret with: `openssl rand -base64 32`

> **Tip:** If you hit 401 errors, double-check that `CORS_ORIGIN` matches your frontend URL exactly -- including protocol, no trailing slash.

### Request rules

- Write requests to `/trpc/*` and `/api/upload` must pass trusted-origin/Fetch Metadata checks (403 otherwise), independently of CORS.
- Actual body bytes are capped at 64 KiB for auth, 1 MiB for ordinary tRPC, and 16 MiB only when every call in the batch is `backup.*`. A mixed batch uses the 1 MiB cap. Understated Content-Length does not bypass counting.
- Batched requests (`/trpc/a,b?batch=1`) may contain at most 20 calls. Contact submissions and retired `public.trackView`/`public.trackClick` requests are rate limited **per call**, so a batch spends one token for each. Retired collectors return NOT_FOUND and write no new activity.
- Errors never include stack traces; unexpected failures return "Internal server error".

## Endpoint Reference

All procedures use `/trpc/<router>.<procedure>`. **Public** procedures need no auth in the legacy serving mode. **Protected** procedures require a valid session cookie. Split-mode external ingress blocks legacy public API access; the admin's private binding remains available. The dedicated public contact action is separate.

### Blocks

Manage content blocks on your page. New blocks start as drafts. `publishAll` marks them eligible for published content; it does not deploy a static revision. The legacy renderer reads saved changes directly, while assets-only publication requires `publication.request` and a verified result.

| Procedure | Type | Auth | Description |
|-----------|------|------|-------------|
| `blocks.list` | Query | Protected | All blocks ordered by `(position, createdAt, id)` |
| `blocks.create` | Mutation | Protected | Create a block. The server appends it at the end (`MAX(position)+1`) unless it is an Undo re-insert, which goes back to its old slot |
| `blocks.update` | Mutation | Protected | Update by ID, validating the resulting type/config and embed provider together |
| `blocks.delete` | Mutation | Protected | Delete a block by ID (its click history is deleted too) |
| `blocks.reorder` | Mutation | Protected | Batch update block positions (max 500) |
| `blocks.toggleEnabled` | Mutation | Protected | Toggle block visibility |
| `blocks.publishAll` | Mutation | Protected | Include every draft block in published source content |
| `blocks.hasDraft` | Query | Protected | `{ hasDraft }`: whether any block is unpublished |

### Settings

Manage site-wide key-value configuration. Every key and value is checked against the settings registry; secret values are masked when read.

| Procedure | Type | Auth | Description |
|-----------|------|------|-------------|
| `settings.get` | Query | Protected | Get a single setting by key |
| `settings.getAll` | Query | Protected | Get all settings as a key-value map |
| `settings.update` | Mutation | Protected | Upsert a single key-value pair |
| `settings.updateBulk` | Mutation | Protected | Upsert multiple key-value pairs in one atomic batch |

### Forms (Inbox)

Contact form submissions. Filters: `isRead?: boolean`, `blockId?: string`.

| Procedure | Type | Auth | Description |
|-----------|------|------|-------------|
| `forms.list` | Query | Protected | Newest first, paged with `limit` (1-100, default 50) and `offset`, plus the filters |
| `forms.count` | Query | Protected | `{ total }` for the same filters, so "n of total" matches the list |
| `forms.markRead` | Mutation | Protected | Mark a submission as read |
| `forms.markUnread` | Mutation | Protected | Mark a submission as unread |
| `forms.delete` | Mutation | Protected | Delete a submission |
| `forms.markAllRead` | Mutation | Protected | Mark every submission as read |
| `forms.deleteMultiple` | Mutation | Protected | Delete up to 100 submissions by ID |
| `forms.unreadCount` | Query | Protected | Count of unread submissions |

### Analytics

The `analytics.*` queries read historical profile records. They do not indicate current collection.

### Publication

| Procedure | Type | Auth | Purpose |
| --- | --- | --- | --- |
| `publication.status` | Query | Protected | Availability, verified last-good receipt, current revision, failure/recovery state, scheduler status, and limits |
| `publication.request` | Mutation | Protected | Freeze saved public source and request an authorized publication; deduplicate unchanged work and bound build frequency |

Publication is disabled by default until an approved target and runner are configured. A saved draft is not a live receipt. The publisher stages immutable assets, verifies activation, and retains last-good recovery; cloud adapter and routing proof still require the designated environment. Scheduled jobs use the approved frozen source, never fresh mutable authoring data.

### Historical analytics queries

Page views and clicks. Every query takes `{ period: "7d" | "30d" | "90d" | "all" }` (default `"7d"`). Daily buckets follow the admin's timezone setting.

| Procedure | Type | Auth | Description |
|-----------|------|------|-------------|
| `analytics.overview` | Query | Protected | Total views and clicks for the period |
| `analytics.viewsOverTime` | Query | Protected | Daily view counts |
| `analytics.clicksOverTime` | Query | Protected | Daily click counts |
| `analytics.topLinks` | Query | Protected | Top 10 links by clicks |
| `analytics.referrers` | Query | Protected | Top 10 referrer hostnames |
| `analytics.countries` | Query | Protected | Top 20 countries by views |

### Social

Social network links shown under the profile.

| Procedure | Type | Auth | Description |
|-----------|------|------|-------------|
| `social.list` | Query | Protected | List saved networks |
| `social.updateBulk` | Mutation | Protected | Create, update or remove networks in one batch |

### Wallet

Configure and sign Apple Wallet passes. The `.pkpass` itself is downloaded from `GET /api/admin/wallet-pass` (session required).

| Procedure | Type | Auth | Description |
|-----------|------|------|-------------|
| `wallet.getConfig` | Query | Protected | Get wallet settings |
| `wallet.updateConfig` | Mutation | Protected | Update wallet settings (fields validated per section; an empty field key is rejected with its section and number) |
| `wallet.getSigningStatus` | Query | Protected | Which signing items are configured **and loadable** |
| `wallet.getSigningKeys` | Query | Protected | Saved Team ID / Pass Type ID and whether each key is saved (never the key material) |
| `wallet.updateSigningKeys` | Mutation | Protected | Save signing material (raw or base64-wrapped PEM, base64 DER certs); unloadable material is rejected with `BAD_REQUEST` |
| `wallet.generatePreview` | Query | Protected | Pass content as the signer would build it |

### vCard

The global vCard (Design → Branding). The public download is `GET /api/vcard` (`?block=<id>` for a vCard block's card).

| Procedure | Type | Auth | Description |
|-----------|------|------|-------------|
| `vcard.getConfig` | Query | Protected | Get the vCard toggle and data |
| `vcard.updateConfig` | Mutation | Protected | Update the vCard toggle and fields |

### Backup

Import and export data.

| Procedure | Type | Auth | Description |
|-----------|------|------|-------------|
| `backup.export` | Query | Protected | Export blocks, non-secret settings, social networks and contact messages; includes `notes` and referenced image keys, not image files |
| `backup.import` | Mutation | Protected | Import a backup in `"merge"` or `"replace"` mode in one atomic batch. Replace keeps secret settings, upserts blocks in place (removing ones missing from the backup) and deletes only messages absent from the backup. Accepts ISO or epoch-ms dates; caps: 500 blocks, 500 settings, 5,000 messages on the wire (newest 500 written). Returns counts plus `skipped.{blocks, socialNetworks, settings, contactSubmissions}` |
| `backup.importLinkStack` | Mutation | Protected | Import a LinkStack export (http(s) links appended after existing blocks, profile, matching theme preset) |

Backup exports do not include publication receipts, signing secrets, or uploaded file bytes.

### Danger

Destructive resets from Settings → Data. Both are audited and run as one atomic batch.

| Procedure | Type | Auth | Description |
|-----------|------|------|-------------|
| `danger.deleteAllContent` | Mutation | Protected | Delete blocks, historical analytics and messages; revoke approved scheduled source while preserving an uncertain in-flight activation; keeps account, settings, social links  |
| `danger.resetEverything` | Mutation | Protected | Wipe every table (including the audit log and the admin account); the client then signs out and returns to setup |

### Version

| Procedure | Type | Auth | Description |
|-----------|------|------|-------------|
| `version.checkUpdate` | Query | Protected | Compare `version.json` with the latest GitHub release. Input `{ force?: boolean }`. Returns `status: "ok" \| "unavailable"` and a `reason` when unavailable. Cached per isolate (6h after success, 10 min after failure); `force` skips the cache but reuses an answer fetched in the last 60s |

### Public

Legacy public-facing procedures. They are not a public fallback for an assets-only deployment.

| Procedure | Type | Description |
|-----------|------|-------------|
| `public.getPage` | Query | Full page data: profile, published blocks, theme, public settings, `captchaProvider` and `captchaSiteKey` (never the secret) |
| `public.submitContact` | Mutation | Submit the contact form. Input: `firstName`, `lastName`, `email`, `consent: true`, optional `message`, `whereMet`, `blockId`, `blockTitle`, `captchaToken`, and a `website` honeypot that must stay empty. Rate limited per call |
| `public.trackView` | Mutation | Retired: bounded legacy inputs return NOT_FOUND; no new records |
| `public.trackClick` | Mutation | Retired: bounded legacy inputs return NOT_FOUND; no new records |
| `public.hasUsers` | Query | Whether an admin account exists |
| `public.getSetupStatus` | Query | Setup complete, email configured, magic-link availability, and normal site branding for sign-in |

All input is validated with shared Zod schemas from `packages/validators`.

### REST routes on the API Worker

| Route | Auth | Description |
|-------|------|-------------|
| `GET /api/health` | Public | D1 check, version, email and auth state (`503` when degraded) |
| `POST /api/upload` | Protected | Multipart `file`, `purpose`, optional unsaved `replaces`; valid Content-Length required; 5 MiB file + 16 KiB framing cap; returns `{ publicUrl: "/api/images/..." }` |
| `GET /api/images/*` | Public | Serve an uploaded image |
| `GET /api/vcard` | Public | vCard download (`?block=<id>` optional) |
| `GET /api/admin/wallet-pass` | Protected | Signed `.pkpass` download |
| `POST /api/contact` | Exact public profile origin; no account credentials | Optional explicit public action; CAPTCHA required, actual 64 KiB body cap, shared 100-reservation UTC daily quota |

In split mode the legacy routes above are reachable through the private admin transport, not an alternate public API hostname. Only an explicitly configured contact action is allowed through public ingress. Existing assets-only profiles serve bundled images/vCards and do not rely on `/api/images/*` or `/api/vcard` per visit.

Upload replacements never delete a saved referenced object immediately. The editor expands a relative upload path to its configured API origin before saving; existing absolute URLs are preserved. See [Security](/docs/guide/security#uploads-and-media) for cleanup and validation behavior.
