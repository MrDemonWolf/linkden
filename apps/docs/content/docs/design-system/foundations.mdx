## How the tokens are organized

The color, type, radius and control tokens live in two files: `apps/web/src/index.css` for the interface, and `packages/ui/src/themes.ts` for the public theme presets. Spacing uses Tailwind's scale directly. Components use semantic utilities such as `bg-card`, `text-muted-foreground` and `border-input-border`, never raw hex values. The color and scale tables below are rendered from those two files when the docs build, so they always show the current values.

| Layer | Defined in | Applies to |
| --- | --- | --- |
| Admin palette | `.admin-scope` and `.dark .admin-scope, .admin-scope.dark` | The admin shell root, plus `<body>` while the console is mounted, so portalled menus, popovers and dialogs get the same tokens (`components/admin/admin-shell.tsx`) |
| Base palette | `:root, .public-scope` and `.dark, .dark .public-scope` | Pages outside the shell that use semantic utilities, such as `/offline`, and every `.public-scope` element: the static build's `<body>` and the admin preview viewport |
| Public theme | `--ld-*` variables from `themes.ts`, resolved by `getThemeColors` (`apps/web/src/lib/theme-colors.ts`) | Set inline on `.ld-page` by `components/public/public-page-content.tsx` for the live page, the static build and the admin preview |
| Tailwind mapping | `@theme inline` maps each semantic variable to a `--color-*` theme key | Utilities such as `bg-surface-2`, `text-primary`, `border-input-border` and `bg-code-surface` |

The `.dark` class sits on `<html>`. In the admin it comes from next-themes (`attribute="class"`, `defaultTheme="dark"`, `enableSystem`) in `components/providers.tsx`, and the footer's theme control changes it. The public page chooses its own mode: the visitor's `linkden-color-mode` cookie, else the `default_color_mode` setting, where `system` follows the browser. That mode is passed to `getThemeColors`.

See [Where each scope applies](/docs/design-system#where-each-scope-applies) on the overview for screenshots of each surface.

Rules for the admin palette:

- `--input` is a fill. Input, Select trigger, Textarea, InputGroup, Checkbox and the off Switch draw their boundary with `--input-border`, which clears 3:1 on the card, ground and inset planes (WCAG 1.4.11). Hand-rolled fields use `border-input-border`, never `border-input`.
- Status text sits on its own 10–20% tint, for example `text-warning` on `bg-warning/10`. The palette regression test, `apps/web/src/components/ui/__tests__/admin-palette-contrast.test.ts`, checks success and warning text on their tints, the control boundary on every plane, and primary and muted text on every content plane, in both modes.
- The dark sidebar uses its own `#111113`; in light it shares `--card`. Other sidebar roles derive from the semantic tokens.
- The PWA status-bar colors in `apps/web/src/app/admin/layout.tsx` (`#FFFFFF` and `#18181B`) mirror `--card`. Change them together.

### Fluid scale

<TypeScale />

The middle term of each `clamp()` uses container query units (`cqw`). The public page root, `.ld-page`, is an inline-size container, so the scale follows the page frame, which is also what keeps the admin preview at phone sizes. Admin containers such as `CardHeader` (`@container/card-header`) and `FieldGroup` (`@container/admin-fields`) do the same for `text-micro`, which is why a card description measures 12.2px rather than exactly 12px. Outside any container, `cqw` falls back to the viewport.

`text-micro` is the floor: nothing in the interface renders below 12px. The miniature Wallet pass canvas has its own smaller label scale; don't copy it into editor forms.

`cn` in `packages/ui/src/utils.ts` registers `h1`, `h2`, `body`, `small` and `micro` with `tailwind-merge`, so `text-micro text-muted-foreground` keeps both the size and the color.

## Spacing and widths

The app uses Tailwind's spacing scale rather than a separate spacing-token file. Common steps in the shared components:

| Step | Pixels | Current examples |
| --- | --- | --- |
| `1` | 4px | `SidebarMenu` and `SubTabs` gaps |
| `1.5` | 6px | Label-to-control groups (`space-y-1.5`) |
| `2` | 8px | Inline actions and icon-to-text gaps |
| `3` | 12px | Public block stack (`space-y-3`), small groups |
| `4` | 16px | `FieldGroup` grid gap, mobile page gutter, compact card padding |
| `5` | 20px | Card vertical padding and header-to-content gap, card side padding from `sm` |
| `6` | 24px | Page rhythm from `sm` (`PageShell`), page gutter from `sm` |
| `8` | 32px | Page padding from `lg`, editor-to-preview gap, settings nav gap |
| `10` | 40px | Public split-layout column gap |

| Element | Value | Source |
| --- | --- | --- |
| Admin main area | 16px / 24px (`sm`) / 32px (`lg`) sides, 24px / 32px (`lg`) top and bottom, capped at 1680px | `admin-shell.tsx` |
| `PageShell` | 16px vertical rhythm, 24px from `sm` | `page-shell.tsx` |
| `Card` | 20px vertical padding, 16px sides (20px from `sm`), 20px gap; `size="sm"` uses 16px padding and a 12px gap | `components/ui/card.tsx` |
| Page without a preview | Max 1120px | `MainGrid` |
| Tool column beside a preview | Max 760px, 32px gap | `MainGrid` |
| Preview column | 300px at `lg`, 372px at `xl`, 425px for the wide Wallet variant, 40px collapsed (44px on touch) | `preview-column.tsx` |
| Sidebar | 256px (`16rem`), 48px icon rail; the primitive's 288px mobile sheet is never shown, because the shell renders no sidebar below `lg` | `components/ui/sidebar.tsx` |
| Settings section nav | 176px column from `xl` | `settings-shell.tsx` |
| Top bar / bottom tab bar | 64px / 56px | `admin-shell.tsx` |
| Public split layout | 320px profile column and a fluid block column from an 896px container (`@4xl`) | `public-page-content.tsx` |

These are source constraints. Don't add more width wrappers inside the shell.

Button heights read the scoped tokens below. Outside the admin the tokens are not set (and `.public-scope` resets them to `initial` inside the preview), so with a fine pointer from `md` Button falls back to 32px `default`, 28px `sm`, 24px `xs` and 36px `lg`, which keeps the public footer buttons small.

<ControlScale />

Details that matter:

- Inputs and Select triggers use 16px text below `md` or on coarse pointers and 14px with a fine pointer (`md:pointer-fine:text-sm`). The 16px size also stops iOS from zooming into a focused field.
- `@media (pointer: coarse)` in `index.css` gives every admin button, input, input group, color input, combobox, settings-section link and footer link a 44px minimum height (buttons and color inputs also a 44px minimum width), so tablets get touch targets even above `md`.
- The Switch keeps its 36×20px track and gets a 44px target from an `after:` pseudo-element (`after:-inset-x-2 after:-inset-y-3`). Don't enlarge the track to match a text field.
- Buttons use `--control-font-size` (14px in the admin) from `md`.

### Surfaces

Admin cards are matte: `bg-card border border-border shadow-surface rounded-lg`, with no blur. Navigation uses solid state fills (`--sidebar-accent`, `--surface-2`), and the Unsaved control uses a warning outline and text with no glow. Public link cards use `shadow-card` with a `backdrop-blur-xl`, and the public hero and the Wallet card have their own treatments. Those don't establish a glass or glow style for admin forms.

### Custom colors

Design → Theme also takes `custom_primary`, `custom_secondary`, `custom_accent` and `custom_background`. They are true overrides and apply in both modes; an empty field inherits the preset. Picking a preset clears them (`clearCustomColors` in `apps/web/src/app/admin/design/theme-form.ts`). `getThemeColors` keeps the result readable:

- A custom background re-derives the foreground only when the preset's foreground falls below 4.5:1 on it.
- When the card and the custom background land on opposite sides of the light/dark line, the card, muted and border colors are rebuilt from the background (4%, 8% and 16% toward the foreground).
- `--ld-muted-foreground` must pass 4.5:1 on the ground, the card and the muted panel. Otherwise it is eased from the foreground toward the background only as far as AA allows.
- Single-color places (the OG card, browser chrome, the manifest) use `pagePrimaryColor`: the custom primary when set, else the preset's light primary.

`ColorField` in the editor shows a contrast guard while you pick.

## Motion

Motion is limited to feedback and real state changes. Admin pages, forms and charts have no decorative entrance animation.

| Motion | Duration and easing | Source |
| --- | --- | --- |
| Public entrance `ld-rise` (hero, blocks, social icons) | 480ms, `--ease-out`, 8px rise; 45ms stagger per `--ld-i`, index capped at 12 | `index.css`, `public-page-content.tsx` |
| Link card hover (lift, border, glow, accent bar) | 220ms ease-out | `components/public/link-block.tsx` |
| Preview column collapse | 220ms width transition | `components/admin/preview-column.tsx` |
| Theme preset tile | 200ms | `theme-presets-section.tsx` |
| Select list open and close | 150ms fade and zoom | `components/ui/select.tsx` |
| Easing tokens | `--ease-out: cubic-bezier(0.22, 1, 0.36, 1)`, `--ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1)` | `@theme inline` |

Reduced motion:

- A global `@media (prefers-reduced-motion: reduce)` rule cuts every animation and transition to 0.01ms, runs animations once and sets `scroll-behavior: auto`.
- That rule is a universal selector, so the `ld-rise` classes would outrank it. A second media rule sets `animation: none` on `.ld-hero`, `.ld-blocks > *` and `.ld-social-icons > a`. Any new class that sets an `animation` shorthand belongs in that list.
- CSS can't reach `scrollIntoView` or `scrollBy({ behavior: "smooth" })`. Imperative scrolls pass `behavior: prefersReducedMotion() ? "auto" : "smooth"` from `apps/web/src/hooks/use-reduced-motion.ts`.
- The public page turns transitions off briefly (50ms) when it corrects a first-visit color mode, so the palette swaps instantly instead of fading.

Every capture in these docs is taken with `reducedMotion: "reduce"`, which is also how you can check that a page settles without its entrance.
