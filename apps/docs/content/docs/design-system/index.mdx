LinkDen has two visual layers. The admin is a compact workspace with neutral surfaces and blue actions. Public pages keep the owner's theme, colors, imagery, and softer shapes. The editor preview renders that same public page inside the admin, so both layers often share one screen.

These pages describe the implemented app. Every value comes from the source files listed in the [source map](#source-map), and every screenshot is a capture of the running app with synthetic sample content. Change the source first, then update the page and recapture its images.

## Two visual layers

Both layers load one stylesheet, `apps/web/src/index.css`. Admin chrome and the shared primitives use semantic utilities such as `bg-card`, `text-muted-foreground`, and `border-input-border`; the scope class around them decides which values those utilities resolve to. Public blocks paint with the owner's resolved theme instead: `getThemeColors` (`apps/web/src/lib/theme-colors.ts`) combines the preset with saved overrides, and the page content projects the result onto `.ld-page` as `--ld-*` variables and inline styles.

Numeric text uses Geist Mono (`.data-mono`, tabular figures) in both layers; the root layout loads it as `--font-mono`. The Wallet pass preview is a third, self-contained surface: it uses the system/SF font stack (`-apple-system, BlinkMacSystemFont, "SF Pro Display", "SF Pro Text", system-ui, sans-serif`) and the pass colors saved under Settings → Wallet.

A saved theme changes only the public layer. With the Sunset preset saved, the editor below keeps its fixed admin palette, while the page inside the preview rail (and the live page) switches to Sunset's colors: in light mode a `#FFFBF5` ground, `#431407` text and a `#C2410C` primary; in dark mode the same `#101012` / `#18181B` grounds as Classic with a `#FB923C` primary. ## Where each scope applies

| Surface | How the scope is applied |
| --- | --- |
| Admin console | `AdminShell` puts `.admin-scope` and the admin font variables on its root, and mirrors both onto `<body>` while mounted so portalled menus, popovers, tooltips, dialogs, and sheets inherit them |
| Login, setup, reset password | The routes in `PUBLIC_ADMIN_ROUTES` (`apps/web/src/lib/admin-routes.ts`) render inside a plain `.admin-scope` wrapper without the sidebar; see [Patterns](/docs/design-system/patterns) for captures |
| Live public page (`/`) | `:root` carries the public token defaults, `body` sets Sora and DM Sans, and `.ld-page` receives the resolved `--ld-*` theme variables as inline styles |
| Static public build | `renderStaticDocument` (`components/public/static-document.tsx`) puts `.public-scope` on `<body>` and renders `StaticPage`, which wraps the same `PublicPage` |
| Page preview | `PagePreviewViewport` wraps the real `PublicPage` in `.public-scope`, marks it `inert`, and exposes it as one `role="img"` named "Live preview of your page" |
| Wallet preview | `WalletPassPreview` sits in the same rail and paints the pass with its own colors and the system font stack |
| Documentation | The Fumadocs Notebook layout with its own palette in `apps/docs/src/app/global.css`; it never redefines app tokens |

The cascade in `apps/web/src/index.css` is ordered so a nested public scope wins inside the admin:

```css
:root, .public-scope { /* public light tokens */ }
.dark, .dark .public-scope { /* public dark tokens */ }
.admin-scope { /* admin fonts, light palette, control heights, tighter radii */ }
.dark .admin-scope, .admin-scope.dark { /* admin dark palette */ }
.public-scope { /* restores public fonts, radii and control-height fallbacks */ }
```

`.admin-scope` and the second `.public-scope` rule are unlayered and declared in that order, so at equal specificity the public rule wins when the two are nested. The radius scale lives in a plain (not inline) `@theme` block, so utilities compile to `var(--radius-*)` and each scope can retune them at runtime. The coarse-pointer rules that raise admin controls to 44px exclude anything inside `.public-scope`.

## Breakpoints at a glance

The admin uses Tailwind's default viewport breakpoints. The public page uses container widths of `.ld-page`, so the same rules hold inside the preview.

| Width | Admin | Public page |
| --- | --- | --- |
| Below 640px (`sm`) | 16px page padding; 24px page heading | Banner 112px |
| 640px (`sm`) | 24px padding; 28px heading | Banner 144px (container width) |
| 768px (`md`) | With a fine pointer, Buttons use the 36 / 32 / 44px control tokens and Inputs and Select triggers drop to 36px with 14px text; otherwise all stay 44px with 16px text | — |
| 896px container | — | `split` becomes two columns: 320px sticky profile and the block stack, 40px apart, up to 1152px wide |
| 1024px (`lg`) | Sidebar (256px, collapsible to a 48px icon rail with Cmd/Ctrl+B) and the 300px preview rail replace the 56px bottom tab bar and the preview sheet; 32px padding | — |
| 1280px (`xl`) | Preview rail 372px; an editor panel stacks above the preview instead of replacing it | — |
| Coarse pointer, any width | Buttons, fields, selects, color inputs, and section links are at least 44px (switches and checkboxes keep their size); fields use 16px text | — |

## Rules that apply everywhere

- **Use semantic utilities.** Write `bg-card`, `text-foreground`, and `border-input-border`, not hex values. A new color is a token in `index.css` first.
- **Keep the layers separate.** The public color controls edit public theme overrides only. There is no admin accent-color picker, and a saved public palette never recolors admin navigation or forms.
- **One renderer.** Preview, live page, and static output use the same public components. Do not fork block markup for the preview.
- **One source for limits.** Accepted settings, block configuration, and pass content come from `packages/validators/src/`. Forms and renderers read those rules instead of restating them.
- **Accessible by default.** Keep visible keyboard focus, label and error associations, the 3:1 `--input-border` control boundary, and the 12px text floor. Color alone never carries state.
- **Honor reduced motion** in CSS and in JavaScript (`prefersReducedMotion()` from `apps/web/src/hooks/use-reduced-motion.ts`).
- **No design-system route in the product app.** These docs are the reference; examples live where the app renders them.

### Regenerate the images

1. Start a disposable stack from a separate worktree: the API on `127.0.0.1:3100` (`wrangler dev` with `DEV_LOGIN=true` and a loopback `BETTER_AUTH_URL`) and the web app on `127.0.0.1:3101`. The README has the exact env files and commands.
2. Seed it from the main checkout. This replaces all content, so never point it at a stack whose data you need. It refuses non-loopback URLs and port 3001.

   ```bash
   bun scripts/design-screenshots/seed.ts
   ```

3. Capture every group, or only the ones you changed:

   ```bash
   bun scripts/design-screenshots/capture.ts            # all groups
   bun scripts/design-screenshots/capture.ts overview   # one group
   bun scripts/design-screenshots/capture.ts --list
   ```

   The runner prints each image's size and exits non-zero when a group fails or an image is over budget. `DESIGN_SHOTS_URL` overrides the default `http://localhost:3101`. To retake single images, `OVERVIEW_ONLY=admin-anatomy,public-footer` (and `FOUNDATIONS_ONLY` for the foundations group) limits a run to shot names with those prefixes.

4. Look at every changed image before you commit it. Retake anything blurry, badly cropped, mid-animation, or showing development overlays.

Capture modules are read-only: they open editors, dialogs, and menus, then discard. They never save, apply, delete, reset, import, or toggle instant-save switches. Captures that need a different saved state belong in the `stateful` group, followed by a fresh `seed.ts` run. Inbox times such as "2h ago" are computed at seed time, so seed shortly before capturing.

### Embed a capture

Import images statically, so the docs export fingerprints them and applies the `/linkden` base path:

```mdx
import adminEditorLight from "./images/overview/admin-editor-light.webp";
import adminEditorDark from "./images/overview/admin-editor-dark.webp";

<Screenshot
  light={adminEditorLight}
  dark={adminEditorDark}
  alt="What the image shows, for someone who cannot see it."
  caption="What to notice."
/>
```

`<Screenshot>` (`apps/docs/src/components/screenshot.tsx`) shows `dark` when the docs are in dark mode and falls back to `light`. `maxWidth` caps narrow captures such as phones and single components. `<ScreenshotGrid columns={2 | 3}>` places related captures side by side from the `sm` breakpoint.

## Changing the system

1. Change the source token, component, or validator.
2. Run the affected tests, including the palette contrast test in `apps/web/src/components/ui/__tests__/admin-palette-contrast.test.ts` for color changes.
3. Update the relevant page here, keeping values and paths exact.
4. Recapture the affected group and review it in light and dark.
5. Check desktop and touch sizes, focus and error states, the real public output, and reduced motion.

A screenshot or local preview shows how the interface looks. It is not proof of publication, pass signing, or a live integration.
