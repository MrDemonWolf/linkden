## Where components live

| Layer | Path | What it holds |
| --- | --- | --- |
| App primitives | `apps/web/src/components/ui/` | Base UI + Tailwind building blocks: `Button`, `Input`, `Textarea`, `Select`, `Label`, `Card`, `Badge`, `Alert`, `Dialog`, `AlertDialog`, `Popover`, `DropdownMenu`, `Tooltip`, `ToggleGroup`, `Tabs`, `Sidebar`, `Skeleton`, `Empty`, `InputGroup`, `SectionRule`, `ThemeToggle`, `Toaster` (Sonner) |
| Shared package | `packages/ui/src/` | `Checkbox`, `Switch`, `Avatar` and `Tabs`, plus theme presets, banner presets, social brands, `color-contrast` helpers and `cn` |
| Admin building blocks | `apps/web/src/components/admin/` | `PageShell`, `PageHeader`, `SubTabs`, `SectionCard`, `SectionHeader`, `SectionLabel`, `ColorField`, `ImageUploadField`, `StickySaveBar`, `StatePill`, `ConfirmDialog`, `EmptyState`, `FieldError`, `CharCount`, `AdminFooter` |
| Settings helpers | `apps/web/src/components/admin/settings/` | `FieldGroup`, `SecretInput`, `DangerConfirmDialog`, `mutationErrorMessage` |

`packages/ui` is not a second copy of every web primitive. The app re-exports its `Switch` (`components/ui/switch.tsx`) and wraps its `Tabs` (`components/ui/tabs.tsx`) to add the 44px touch floor.

Import the existing component from its owning module. Do not install another component library to recreate a button, dialog, form grid or preview.

| Variant | Look | Used for |
| --- | --- | --- |
| `default` | `bg-primary`, `text-primary-foreground`; `hover:bg-primary/80` | The one primary action: Save changes, Apply n new, Publish, Crop & upload |
| `outline` | `border-border bg-background`; dark: `bg-input/30` | Secondary actions: View live, Change, Delete (Danger zone), Retry, Cancel in alert dialogs |
| `secondary` | `bg-secondary`, hover mixes 5% foreground | The share popover's "Share…" button, shown only when the browser supports `navigator.share` |
| `ghost` | Transparent; `hover:bg-muted` | Discard, Refresh status, icon triggers, settings nav items, upload Replace/Re-crop/Remove |
| `destructive` | `bg-destructive/10 text-destructive`; dark: `bg-destructive/20` | Delete, Reset everything, Reset… |
| `link` | `text-primary`, `underline-offset-4`, underline on hover | Back to sign in and "Use a backup code instead" on the login page |

| Size | Touch (below `md`, or coarse pointer) | Admin, fine pointer from `md` | Outside `.admin-scope` (fallback) |
| --- | --- | --- | --- |
| `default`, `icon` | 44px | `--control-height` = 36px | 32px |
| `sm`, `icon-sm` | 44px | `--control-height-compact` = 32px | 28px |
| `xs`, `icon-xs` | 44px | `--control-height-compact` = 32px | 24px |
| `lg`, `icon-lg` | 44px | `--control-height-large` = 44px | 36px |

Text is 14px (`text-sm`) below `md` and `--control-font-size` from `md` (14px in the admin, 12px fallback). `xs` and `sm` share a height in the admin; `xs` differs only in its tighter side padding (`px-2.5` instead of `px-3`), and both use a 6px gap and 14px icons. The `@media (pointer: coarse)` rule in `apps/web/src/index.css` sets all three control heights to 44px, so tablets keep touch targets. See [Controls](/docs/design-system/foundations#controls).

```tsx
import { Button } from "@/components/ui/button";

<div className="flex flex-wrap items-center gap-2">
  <Button disabled={isSaving} onClick={save}>
    {isSaving ? "Saving…" : "Save changes"}
  </Button>
  <Button variant="ghost" disabled={isSaving} onClick={discard}>
    Discard
  </Button>
</div>
```

- Keep a visible label for text actions. Icon-only buttons need an `aria-label` (Share is "Share your page").
- Use `disabled` to block repeat actions while a request is pending. Disabled buttons drop to 50% opacity and ignore pointer events.
- `aria-invalid` applies the shared error treatment (`border-destructive`, `ring-destructive/20`).
- Focus shows `border-ring` plus a 2px `ring-ring/50`. Pressing nudges the button down 1px (`active:translate-y-px`), except for menu triggers.
- Navigation is a link, not a button. Render a real `<Link>` or `<a>` and give it the button look with `buttonVariants({ variant, size })` from `components/ui/button.tsx`: the Settings nav, View live, Open live page, the Inbox Reply link, Download pass, EmptyState link actions and Update to … all do this, so they keep the link role and open with Enter. Do not render an anchor through `Button` (`nativeButton={false}` with `render={<a />}`): Base UI then adds `role="button"`, and screen readers announce the link as a button.
- Do not override heights per page. The sizes above come from the scoped tokens.

| --- | --- | --- |

`FieldError` renders only after an error has been stable for 700ms (`delay`), so a half-typed URL does not flash red on every keystroke. It clears at once when the value becomes valid. It is a `role="status"` paragraph in `text-micro text-destructive`. `CharCount` prints `n/max` in `text-micro` and turns destructive past the limit.

```tsx
import { CharCount, FieldError } from "@/components/admin/field-feedback";
import { Input } from "@/components/ui/input";
import { Label } from "@/components/ui/label";

<div className="space-y-1.5">
  <Label htmlFor="profile-name">Display name</Label>
  <Input
    id="profile-name"
    value={name}
    onChange={(event) => setName(event.target.value)}
    aria-invalid={error ? true : undefined}
    aria-describedby={error ? "profile-name-error" : "profile-name-help"}
  />
  <p id="profile-name-help" className="text-micro text-muted-foreground">
    Shown at the top of your public page.
  </p>
  <FieldError id="profile-name-error" error={error} />
  <CharCount value={name} max={50} />
</div>
```

- Associate help and error text with `aria-describedby`, and set `aria-invalid` only while the value is invalid.
- Validate with the shared schemas in `@linkden/validators` (`fieldError`, `schemaErrors` and `configErrors` in `lib/validate.ts`). Descriptions and limits must match the values the API accepts.
- Hand-rolled fields use `border-input-border`, never `border-input` (`--input` is a fill only).

| Prop | Type | Notes |
| --- | --- | --- |
| `id`, `label` | `string` | The swatch is labeled "`label` color" |
| `value`, `onChange` | `string`, `(value: string) => void` | An empty value is allowed: it inherits the theme or preset default |
| `placeholder` | `string` | Shown when empty; also the swatch color when the value is empty or invalid |
| `contrastAgainst` | `{ hex, label }` | Enables the live ratio line and the Fix chip |

- On blur the value is normalized: `#RGB` becomes `#RRGGBB`, a missing `#` is added and the result is uppercased. An unparseable value shows "Enter a valid hex colour, e.g. #0FACED" immediately (`FieldError` with `delay={0}`).
- The swatch only ever receives a valid 7-character value. It falls back to the placeholder, then `#FFFFFF`, never `#000000`.
- The ratio line is `text-success` at 4.5:1 or more and `text-warning` below it, reading "fails AA (4.5:1 needed)". Fix (outline xs) sets the readable text color from `getReadableTextColor`.
- The swatch is a direct child of the group, not an `InputGroupAddon`: the addon would refocus the text input and fight the native picker.

| Where | Contrast checked against |
| --- | --- |
| Design → Theme: Primary | The background of the previewed mode (`custom_background` or the preset's) |
| Design → Theme: Secondary, Accent, Background | Not checked: these are surface tints |
| Settings → Wallet: Foreground, Label | The pass background |
| Block editor: Custom text | The block's custom background |

- The server returns a saved secret as `SECRET_MASK` (`"••••••"`) and ignores the mask on save.
- Focusing a masked field selects the mask, so the next keystroke or paste replaces it. `editMaskedSecret` strips any remaining mask characters from an edit.
- While the mask shows and `hintId` is set, the field shows "Saved — type or paste a new value to replace it" and adds it to `aria-describedby`.
- `type="password"` fields use `autoComplete="new-password"`; others use `off`. Spell checking is always off.
