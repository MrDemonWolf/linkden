title: Environment Variables
description: Deployment, split publication and local development configuration.

Copy `.env.example` as a starting point, then configure the intended environment. Its local HTTP examples are not production values.

```bash
cp .env.example packages/infra/.env
```

Deployments read `packages/infra/.env` or CI values. Alchemy development also loads app-specific `.env` files; standalone Wrangler reads `apps/server/.dev.vars`, and standalone Next.js uses `apps/web/.env.local`. Do not rely on a development-only file to configure a deployment.

## Required app configuration

| Variable | Purpose |
|----------|---------|
| `BETTER_AUTH_SECRET` | Session/auth secret. Generate a separate random value with `openssl rand -base64 32`; deployment requires at least 32 characters and rejects the public default. |
| `BETTER_AUTH_URL` | Bare origin the browser uses for authentication. |
| `CORS_ORIGIN` | Exact admin/browser origin, including protocol and port where applicable; no trailing slash. |
| `NEXT_PUBLIC_SERVER_URL` | Browser API origin, baked into the web build. |
| `NEXT_PUBLIC_SITE_URL` | Public profile origin used for metadata, sitemap and links; baked into the web build. |

Deploy validation requires HTTPS URLs and matching mode-specific origins. A missing/unsafe auth secret disables protected routes and reports `auth: "misconfigured"` through health checks. Restarting or redeploying with a different auth secret invalidates existing sessions.

### Legacy serving (default)

`LINKDEN_SERVING_MODE` defaults to `legacy`. All four URL values use the web origin, including `workers.dev` staging. Browser requests use the web Worker's API bridge/service binding rather than the API Worker's separate hostname.

```bash
LINKDEN_SERVING_MODE=legacy
SITE_DOMAIN=links.example.com
BETTER_AUTH_URL=https://links.example.com
CORS_ORIGIN=https://links.example.com
NEXT_PUBLIC_SERVER_URL=https://links.example.com
NEXT_PUBLIC_SITE_URL=https://links.example.com
```

`SITE_DOMAIN` is optional in legacy mode. When present, Alchemy attaches the web custom hostname and the API's `/api/*` and `/trpc/*` routes there. See [Custom Domain](/docs/self-hosting/custom-domain) before changing DNS or existing routes.

### Split serving (opt-in)

| Variable | Purpose |
|----------|---------|
| `LINKDEN_SERVING_MODE` | Set exactly `split` for the separately approved routing cutover. |
| `ADMIN_SITE_URL` | Bare HTTPS custom origin for the editor and browser authentication/API. Must differ from public. |
| `PUBLIC_SITE_URL` | Bare HTTPS public profile origin. Also defines the allowed public-contact Origin. |
| `PUBLIC_CONTACT_URL` | Optional exact HTTPS `/api/contact` action on an approved custom hostname distinct from admin. Without it, the API has no public route. |

Leave `SITE_DOMAIN` unset. Set `BETTER_AUTH_URL`, `CORS_ORIGIN` and `NEXT_PUBLIC_SERVER_URL` to `ADMIN_SITE_URL`; set `NEXT_PUBLIC_SITE_URL` to `PUBLIC_SITE_URL`.

The serving mode is part of the web build hash. Changing a runtime value alone does not switch the built app. Split mode requests closed Workers/preview aliases and checks provider state, but does not provision an admin Access policy. Public delivery, alternate-URL closure and Access protection still require cloud verification.

## Cloudflare and Alchemy

| Variable | Purpose |
|----------|---------|
| `CLOUDFLARE_API_TOKEN` | Scoped token for the approved Workers/D1/R2 operation and, when needed, custom-domain/route/DNS/certificate changes. Never a browser value. |
| `CLOUDFLARE_ACCOUNT_ID` | Target Cloudflare account ID. |
| `ALCHEMY_PASSWORD` | Encrypts secrets in Alchemy state. Preserve it and the state store across upgrades. |
| `ALCHEMY_STATE_TOKEN` | Token for the configured shared state Worker. Third-party self-hosters must configure their own store. |
| `ALCHEMY_STAGE` | Defaults to `prod`. Other stages use suffixed resource names; inspect the exact target before deploying or destroying it. |
| `LINKDEN_DB_NAME` | Existing production D1 name to adopt for an upgrade/restore; ignored outside `prod`. |
| `LINKDEN_IMAGES_BUCKET` | Existing production image bucket name to adopt; ignored outside `prod`. |
| `SETUP_TOKEN` | Recommended first-run secret. The initial signup sends it in `x-setup-token`; the setup wizard provides a field. |
| `LINKDEN_CONFIRM_DESTROY_PROD` | `yes` permits the otherwise refused production destroy operation. This is destructive operations configuration, not normal setup. |

Production D1/R2 use `delete: false` after that configuration has been recorded in state. This is not permission to destroy or repoint an existing installation.

## Public publisher API bindings

These are server-only opt-ins supplied to the API by the app deployment:

| Variable | Purpose |
|----------|---------|
| `PUBLICATION_ENABLED` | Exactly `true` enables an approved target; omitted/false leaves publishing off. |
| `PUBLICATION_TARGET` | `staging` or `production`. |
| `PUBLICATION_RENDERER_SOURCE_ID` | Approved full 40-character `main` commit SHA for the renderer. |
| `PUBLICATION_GITHUB_TOKEN` | Private token allowed to dispatch the fixed publication workflow. Never place it in saved browser settings or public snapshots. |
| `PUBLIC_SITE_URL` | Approved public origin for snapshots and verification. |
| `PUBLICATION_SCHEDULER_ENABLED` | Exactly `true`, with enabled publication, installs the optional five-minute boundary tick. |

Enabling these bindings is not proof that the runner, environment approvals, target, credentials or routing work. The default disabled status does not query publication tables, allowing existing editor databases to operate while publication stays off.

## Public publisher environments

The workflow uses `public-staging` and `public-production`. Configure their required reviewers and branch policy before enabling them. Automation is currently pinned to `MrDemonWolf/linkden` and `main`; forks need a reviewed adaptation of the workflow, dispatcher and runner checks.

| Variable or secret | Purpose |
|--------------------|---------|
| `PUBLICATION_RUNNER_APPROVED` | Environment variable exactly `true`; explicit owner opt-in. |
| `PUBLICATION_RENDERER_SOURCE_ID` | Same approved full renderer SHA used by the API. The job must run that exact `main` commit after successful CI. |
| `PUBLIC_SITE_URL` | Exact public target origin. |
| `PUBLICATION_DATABASE_ID` | Actual D1 database ID holding the frozen publication job, not its display name. |
| `PUBLICATION_IMAGES_BUCKET` | Optional R2 bucket containing approved referenced public uploads. |
| `PUBLICATION_IMAGE_ORIGINS` | Optional JSON array of explicitly approved bare HTTPS legacy upload origins; not an arbitrary-fetch allowlist. |
| `PUBLICATION_CONTACT_ACTION` | Optional public contact action URL in the built page. Match the API deployment's `PUBLIC_CONTACT_URL`. |
| `CLOUDFLARE_ACCOUNT_ID` | Environment secret selecting the Cloudflare account. |
| `CLOUDFLARE_PUBLICATION_TOKEN` | Environment secret for the publication operation; mapped to `CLOUDFLARE_API_TOKEN` inside the job. |

The workflow supplies `PUBLICATION_TARGET`, `PUBLICATION_OPERATION`, `PUBLICATION_REVISION`, `PUBLICATION_SOURCE_DIGEST` and `PUBLICATION_JOB_RENDERER_SOURCE_ID` from validated dispatch inputs. It supplies normal `GITHUB_*` and `CI` job context. Do not invent these job identities in the browser.

The staging public target uses its approved canonical Workers hostname; production uses an approved custom hostname. The separate target must already be owned and bootstrapped with preview aliases closed. Local artifact generation does not create those resources.

### Optional Access smoke-test credentials

`CF_ACCESS_CLIENT_ID` and `CF_ACCESS_CLIENT_SECRET` are paired `production` environment secrets for smoke probes through an approved admin Access policy. Both must be present together. They are sent only to admin health/OG probes, not public assets or redirect destinations. They do not create an Access policy.

## Settings managed in the editor

| Setting | Location |
|---------|----------|
| Resend key, verified sender and contact delivery | Settings → Email |
| CAPTCHA provider and keys | Settings → Integrations |
| Wallet design, IDs and signing material | Settings → Wallet |
| Public branding, vCard and embedded-media consent | Design → Branding |
| Magic links, two-factor, timezone and admin branding | Settings → Account |

MapKit and dedicated login-background/logo controls are no longer exposed. Existing compatibility keys remain accepted for backup/restore and are not silently cleared by unrelated saves. Resend is the supported email provider; choosing a future provider is not available in this UI.

## Optional Apple Wallet signing fallback

Settings → Wallet can store signing material; saved values take precedence over environment fallbacks. Downloads are authenticated admin actions, not a public visitor endpoint.

| Variable | Purpose |
|----------|---------|
| `WALLET_SIGNER_CERT` | Pass Type signing certificate. |
| `WALLET_SIGNER_KEY` | RSA signing private key. |
| `WALLET_SIGNER_KEY_PASSPHRASE` | Passphrase when that key is encrypted. |
| `WALLET_WWDR_CERT` | Apple WWDR intermediate certificate. |
| `WALLET_TEAM_ID` | Apple Developer Team ID. |
| `WALLET_PASS_TYPE_ID` | Pass Type identifier. |

Certificates accept raw/base64 PEM or base64 DER; keys accept supported RSA PEM forms, not `.p12` bundles. Missing or unusable material blocks signing. The UI preview is not proof of a pass accepted by Apple Wallet; see the [Wallet guide](/docs/guide/apple-wallet).

## Local development only

| Variable | Purpose |
|----------|---------|
| `DEV_LOGIN` | Exactly `true` in standalone Wrangler's local `.dev.vars` enables the development endpoint only with strict plain-HTTP loopback auth/request/Host/origin/proxy checks. Explicit non-development runtime modes disable it. Never bound by Alchemy. |
| `NEXT_PUBLIC_DEV_LOGIN` | Local development UI opt-in. It does not bypass the server boundary and does not enable a production-page login button. |
| `INTERNAL_SERVER_URL` | Strict bare HTTP loopback target for standalone Next.js API bridging and SSR when no Worker service binding exists. Set it in the recommended local development setup; it also supports local production-build previews. Never a public/tunnel target. |
| `DEV_API_ORIGIN` | Local Next.js rewrite target for standalone API development. |
| `PW_BASE_URL` / `PW_API_URL` | Local Playwright web/API target overrides. |

Deployment smoke tests and local development checks are different evidence. Never enable a bypass or change production routing to make a local check pass.
